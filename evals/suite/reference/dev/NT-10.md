# NT-10: A rate notice that confirms the rate already in effect

World: `employerRateInEffect:CA:sui:0.015` sets the CA SUI rate in effect to 1.5% (as if a person had entered the
revised rate when an earlier copy of the letter came by mail), then `agencyNoticeScenario:ca_de2088_rate_change`
stores the CA EDD DE 2088 notice as ntc_9502, matched to the CA EDD account, with no event. The notice states
"1.5% (previously 3.4%)", so its new rate equals the rate in effect on its effective date, 2026-01-01. The task emits
`notice.received` for ntc_9502.

Nothing changes, so nothing is proposed: no `tax.update_rate` (it would read "1.5% to 1.5%", and the command now
refuses it with DOMAIN_NO_CHANGE) and no `notices.send_response`. The precheck compares each stated rate with the
rate in effect (through `tax.rate_change_impact`, not the notice's own "previously" figure), derives the
acknowledge-only plan and skips the run with the acknowledgment as its reason. The end state has no rate or reply
proposal, the CA SUI rate still 1.5% on its one row, and one skipped routine run. Solvable: the precheck decides in
code from the notice and the rate table; no model call is needed.
