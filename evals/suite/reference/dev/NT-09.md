# NT-09: A second copy of the same letter

The notice simulator delivers the CA EDD DE 2088 rate notice twice, the second after the first routine run settles
(a mailing delivered twice, or a mailed notice that is also uploaded). Each copy is its own notice row with its own
`notice.received` event.

The first run proposes `tax.update_rate` (CA SUI 0.015 effective 2026-01-01) and `notices.send_response`, as RT-01.
The second copy has the same agency, form, account, parsed fields and text as the first, and `notices.get` reports it
as `duplicate_of` the first, which is being handled. The precheck skips the second run with a reason naming the first
notice, so the end state has two DE 2088 notices, two routine runs and one proposal of each command. Solvable: the
first run is RT-01; the second needs no model call.
