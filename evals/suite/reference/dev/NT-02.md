# NT-02: Deposit schedule change notice

The IRS CP136 deposit schedule notice starts
rt_agency_notice. No `tax.update_rate` proposal; the run drafts a reply or escalates with the new schedule from the
parsed fields. Solvable: the parser marks the kind deposit_schedule_change.

Round 2: the end state now requires the notice to be handled (an executed or proposed `notices.escalate`, or a
`notices.send_response` draft). Round 1 passed this task vacuously: the rt_agency_notice precheck skips every notice
that is not a rate change, so no agent run starts and nothing is drafted or escalated. The task fails until the notice
routine handles the other kinds.

Round 3 (FG5): a proposed `tax.set_deposit_schedule` also counts as handling the notice: it is what the notice planner proposes for a deposit schedule change (cross-group contract with FG1).
