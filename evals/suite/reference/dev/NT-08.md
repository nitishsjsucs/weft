# NT-08: The same notice arrives twice

World: `agencyNoticeScenario:ca_de2088_rate_change` stores the CA EDD DE 2088 rate notice as ntc_9502, matched to the
CA EDD account, with no event. The task emits `notice.received` for ntc_9502 twice, the second after the first
routine run settles (an event redelivered for a notice the routine already handled).

The first run proposes `tax.update_rate` (CA SUI 0.015 effective 2026-01-01) and `notices.send_response`, exactly as
RT-01. The second run must file nothing new: `notices.get` lists both open proposals, so the precheck skips the run
with a reason that names them, and an equivalent tool call would get the open proposal back from the executor
instead of a second one. The end state has one proposal of each command, none superseded, and two routine runs.
Solvable: the first run is RT-01; the second needs no model call.
